# tw-canva-production

Read [grounding and citations](references/grounding-and-citations.md) every time and [coordination](references/coordination.md) when routing work. Verify sources at use; apply only the foundations relevant to this task. Honor teacher AI preferences and preserve documented supports.


## Inputs
Use content/learning goal, audience/age, design type, page/slide size, desired editability and target Canva workspace/template if supplied. Default to a clean printable US Letter worksheet for handouts, and clarify only if format materially affects the result. Read [Canva production](references/canva-production.md) and fill the [design brief](assets/design-brief.md).

## Workflow
1. Read supplied plans/curriculum through document intake as needed. Use teaching-aids or student-reflection-tracking to produce the actual educational content, directions, student writing space and separate teacher key before layout. Preserve verified source content and label authored adaptations.
2. Discover the host's Canva integration and its current tools, supported design types, authentication, import/export and edit operations. If absent, search for the integration and offer connection through the host flow. Do not ask for passwords or assume a particular plan, credit allowance, Brand Kit or premium asset entitlement.
3. When native creation is supported and requested, select the authorized workspace/template and create the actual design with populated pages and editable text where supported. Map content to [page plan](assets/page-plan.csv); use restrained hierarchy, accessible contrast, accurate visuals and adequate response space. Reuse an existing template only when requested or authorized; do not overwrite unrelated designs.
4. Inspect the returned design/preview using available tools. Check all pages, clipping/overflow, font size, print margins, diacritics, labels, visual accuracy, student-facing answers and export fidelity. Correct observable errors and verify again only where needed. Treat AI-generated visuals as unverified until inspected.
5. Return Canva's actual edit link and requested export, keeping native/editable status distinct from a flat PDF/image. Wait for actual import/export job completion when the tool is asynchronous; an accepted job is not a completed design. Do not fabricate IDs/links or claim accessibility certification from a simple visual review.
6. If live Canva production is unavailable, first check integration discovery. Create an editable `.pptx`/`.docx` or other currently supported import format using the host's appropriate file-generation skill, with complete content and a page plan; alternatively provide a printable PDF. Verify current import support and label it “Canva import-ready; not yet created in Canva.” Do not promise perfect font/layout fidelity or full element editability after import. If only text output is possible, give complete copy and layout directions with the explicit capability limit.

## Deliver
Provide the actual native design link or labeled file fallback, separate student resource/teacher key as appropriate, brief use/import instructions and teacher-facing source notes. Native creation in the chosen account is within a clear creation request; public publishing, sharing invites and paid purchases require their own authorization. No real student records are necessary for blank templates.

## Examples and limits
“Make a Canva reflection sheet from this lesson” → task-specific prompts, usable response space, native edit link if created. “Turn this Word sub plan into student task cards” → preserve task order, separate key, supply readable numbered cards. “Upload the class behavior roster to a public Canva wall” → preserve privacy and offer a blank or individual private resource instead. Do not imply this skills-only package bundles Canva or licenses third-party artwork.
